# Rustgo 中文 Web、GUI 功能闭环与设备注册设计

## 1. 目标与范围

本阶段在不改变既有隧道、P2P、遥测和静态客户端认证语义的前提下完成三项工作：

1. 将 Web 管理界面的所有用户可见文案改为纯中文。
2. 补齐 `rustgoc-gui` 已有 V0.4 功能的真实数据接线，并加入单个 `client.toml` 的配置管理。
3. 增加由服务器生成一次性接入密钥、客户端自动生成设备密钥并绑定公钥的注册流程，消除人工复制 `.pub` 的步骤。

CLI 与 GUI 必须使用同一个 `rustgoc` 注册与认证实现。GUI 不得重新实现协议、令牌验证或密钥生命周期。

本阶段不包含多配置档案、服务器 root/SSH 凭据托管、云账户体系、长期共享密码、自动升级、移动端客户端或多语言切换。Web 采用纯中文，不增加语言选择器。

## 2. 身份模型

服务端为每条动态客户端记录保存：

- 不可变内部 UUID，用于数据库关系、历史连续性和审计；
- 用户可修改且全局唯一的客户端 ID，用于 Web、GUI、CLI 和日志显示；
- 当前设备公钥；
- 单调递增的凭据版本 `credential_revision`；
- 启用状态、创建时间、更新时间和最近注册时间。

内部 UUID 和设备公钥不在日常 Web 页面显示。客户端 ID 可在 Web 修改并立即生效；在线状态、后续日志、总览、客户端详情和会话视图使用新名称，无需客户端重连。历史数据通过内部 UUID 保持连续。

设备公钥是认证依据。客户端不配置、不保存也不发送服务端内部 UUID。认证成功后，服务端按公钥绑定解析客户端记录，并向客户端返回当前可读客户端 ID。

既有 `server.toml [[clients]]` 静态客户端继续兼容。旧 `client.toml` 中存在可读私钥且未声明身份模式时按静态模式运行，握手字节保持不变；未声明身份模式且没有私钥时进入等待接入密钥，成功后配置原子写入 `identity_mode = "dynamic"`；显式 `identity_mode = "static"` 却缺少私钥仍是静态配置错误。动态模式不使用本地名称选择身份。动态客户端不得覆盖或抢占静态客户端 ID；静态记录不被自动迁移。

新的动态客户端 ID 统一按 UTF-8 字节校验：去除首尾空白后长度为 1–64 字节，仅允许 ASCII 字母、数字、点、下划线和连字符，按 ASCII 小写做动态记录唯一性比较，禁止控制字符。Web、服务端和 SQLite 唯一索引必须使用同一规范。既有静态客户端名称继续按原 UTF-8 字节精确匹配和精确判重，升级不得因中文名称或仅大小写不同而拒绝启动；创建或改名动态记录时，若其 ASCII 小写值与任一纯 ASCII 静态名称的 ASCII 小写值相同则拒绝。设备公钥在静态与动态命名空间全局唯一；服务启动检查、配置检查、首次注册和换钥发现公钥冲突时均失败关闭。

## 3. 一次性接入密钥

管理员在 Web 新建客户端记录并填写客户端 ID 后，服务端生成一次性接入密钥。该密钥：

- 包含版本、规范化服务器连接地址、服务器证书 SHA-256 指纹和高熵随机令牌；服务端对完整编码计算带盐哈希，任何字段被修改都会导致令牌校验失败，另加非安全校验码用于客户端尽早发现复制错误；
- 在 Web 中只显示一次，可复制但不可再次读取；
- 明文不进入数据库、日志、URL、命令行参数或客户端配置；
- 服务端只保存完整编码的带盐哈希、用途、目标内部 UUID、签发时凭据版本、创建时间、过期时间、消费状态，以及成功消费时写入的公钥和请求幂等 ID；
- 默认只能成功消费一次，错误请求或事务失败不得提前消费；
- 有明确大小上限、有效期和全局/单来源尝试限制。

普通注册密钥只能绑定尚无公钥的目标记录。重新注册密钥只能替换其明确关联的已有客户端公钥，不能创建新记录或抢占其他客户端。每次生成重新注册密钥先撤销该客户端所有未消费的旧重新注册密钥；提交时按签发时 `credential_revision` 做 CAS，成功后递增版本并再次撤销其他旧令牌，因此旧令牌不能覆盖新公钥。

未绑定且未墓碑的客户端记录可显式重新签发普通注册密钥。重新签发以记录 revision 做 CAS，并在同一事务内撤销该记录全部旧普通注册密钥；旧明文永不恢复。创建响应丢失或密钥丢失、过期时，重复创建只返回“记录已存在且未绑定”，管理员再执行重新签发。

接入密钥不包含服务端私钥，也不允许推导其他客户端凭据。接入密钥来自已认证的管理员 Web 会话，是首次带外信任根；客户端必须在发送注册秘密或公钥前验证目标服务器地址及其叶证书 DER 的 SHA-256 指纹。地址规范为 `host:port`，IP 直接作为目标，DNS 名同时作为 SNI；首次注册只以精确指纹校验 TLS，注册完成后把地址、指纹和 `trust_mode = "pinned"` 原子写入 `client.toml`。若密钥地址与现有配置冲突，CLI/GUI 必须明确展示差异并经用户确认，不能静默覆盖。本阶段证书轮换只允许管理员生成定向重新注册密钥，客户端按显式重新注册流程同时换设备密钥和服务器指纹；这会终止当前会话并造成一次正常重连窗口，不提供独立信任更新令牌。

## 4. 首次注册流程

1. Web 创建客户端记录并生成一次性接入密钥。
2. 未声明身份模式且找不到设备私钥时进入 `RegistrationRequired`；显式静态模式缺钥保持配置错误，动态模式缺少或损坏正式私钥进入 `ReRegistrationRequired`，而不是无限重连。
3. GUI 显示密码输入框；交互式 CLI 从终端读取；无人值守 CLI 只允许通过标准输入或专用环境变量读取。接入密钥不得作为命令行参数。
4. 客户端解析接入密钥，验证版本、服务器地址和证书指纹，然后建立受指纹约束的 TLS 连接。
5. 客户端在本机生成 Ed25519 设备密钥和随机幂等 ID，先以仅当前用户可读的权限原子写入候选私钥与不含接入密钥的 pending 元数据，并对文件及父目录完成持久化屏障；pending 元数据包含格式版本、pending 类型、候选私钥路径、幂等 ID、规范化服务器地址、叶证书指纹和信任模式。私钥始终留在本机，只上传公钥。
6. 服务端在一个事务内验证令牌、确认目标记录尚未绑定、绑定公钥并消费令牌，同时记录幂等 ID。
7. 服务端返回当前客户端 ID 和注册成功结果；同一目标、同一公钥和同一幂等 ID 的重试返回既有成功结果，其他重放均拒绝。
8. 客户端将候选私钥原子提升为正式私钥，把服务器地址、私钥路径、指纹、信任模式和动态身份模式一次性写入配置，清除内存中的接入密钥，并立即进入正常认证连接。

任一步骤失败时必须保留可恢复状态。服务端事务失败不能留下“令牌已消费但公钥未绑定”的半完成记录；响应丢失或客户端崩溃后，客户端先使用 pending 候选公钥尝试动态认证，成功即完成本地提升，未绑定则重新等待用户输入一次性密钥。接入密钥始终不落盘。客户端持久化失败时必须明确报告，不能声称注册完成。

启动时状态判定顺序固定为：合法 `ReEnrollmentPending` 恢复重新注册；合法 `EnrollmentPending` 恢复首次注册；显式动态模式缺少或损坏正式私钥进入重新注册；显式静态模式缺钥报配置错误；未声明模式且有可读私钥走旧静态认证；未声明模式且无私钥等待首次注册。pending 元数据损坏、字段不完整、权限不安全或与候选私钥不匹配时失败关闭并要求用户显式清理或重新注册，不得猜测状态或覆盖文件。

## 5. 重新注册流程

设备私钥缺失、损坏或用户明确要求换钥时，客户端保持离线并进入 `ReRegistrationRequired`。普通网络失败、TLS 超时或一次认证拒绝不得自动删除私钥或触发重新注册。

重新注册步骤：

1. 管理员在 Web 的目标客户端详情页生成重新注册密钥。
2. 用户在 CLI/GUI 明确选择重新注册并输入该一次性密钥。
3. 客户端验证密钥携带的服务器地址与证书指纹。
4. 客户端生成新设备密钥和幂等 ID，先持久化候选私钥与 pending 元数据；用户确认后直接删除损坏或旧私钥，再提交新公钥。
5. 服务端确认令牌用途、目标内部 UUID 和签发时凭据版本，在一个事务内以 CAS 替换公钥、递增凭据版本、消费当前令牌并撤销其他旧令牌。
6. 服务端立即终止该客户端凭旧凭据建立的控制与数据会话；客户端将候选私钥提升为正式私钥并使用新身份连接。

删除本地私钥是不可恢复操作。GUI 必须在执行前显示明确确认；CLI 必须要求显式 `re-enroll` 操作。候选私钥必须先持久化成功，才允许删除旧私钥；删除后若远端提交失败，保留候选文件和 pending 状态供再次输入密钥重试。若响应丢失，候选公钥动态认证成功即完成提升。客户端必须显示具体阶段，不得静默退回普通连接。

## 6. 注册协议与边界

注册使用独立、版本化、有界的 TLS 消息族，不复用普通客户端认证成功后的业务消息。协议必须限制令牌、公钥、客户端 ID 和错误文本的长度，并为读取、写入和整个注册事务设置截止时间。

动态客户端的普通认证先由握手消息提交设备公钥及其签名证明，服务端按公钥指纹查找唯一动态记录，再验证签名、启用状态和密钥绑定。客户端 ID 不是认证选择器。静态客户端继续走既有名称与公钥校验路径；两条路径共享后续会话、隧道和限流实现。协议协商必须保持旧客户端可识别、可拒绝或继续使用静态认证，不能把新增字段无条件塞入旧消息。

独立“生成设备密钥”只服务于静态身份配置；动态模式只能通过注册状态机生成密钥，并在完成前保持 `EnrollmentPending` 或 `ReEnrollmentPending`，不得拿未绑定密钥进入普通连接循环。

服务端返回稳定、非敏感的错误类别：密钥格式错误、服务器指纹不符、令牌错误、令牌过期、令牌已使用、用途不符、客户端已绑定、客户端被禁用、公钥冲突、容量不足和服务暂时不可用。公开错误不得泄露令牌是否接近正确、其他客户端名称或内部 UUID。

注册尝试纳入现有未认证连接并发限制和速率限制。令牌比较使用恒定时间操作。明文接入密钥和设备私钥不得出现在 `Debug`、错误链、tracing 字段、数据库、URL 或后续查询响应中。唯一例外是第 8 节定义的创建客户端、重新签发普通注册密钥、生成重新注册密钥这三类 POST 的首次成功响应；该响应必须设置 `Cache-Control: no-store` 和 `Pragma: no-cache`，前端只保存在当前页面内存中，刷新、后退、重试或后续 GET 均不能再次取得明文。

## 7. 动态客户端持久化

动态客户端、一次性令牌和安全审计使用独立于观测历史库的服务端 SQLite 权威库，路径由 `server.toml` 配置并提供位于服务状态目录下的兼容默认值。schema 迁移必须事务化并具有明确版本。动态认证读取可使用内存快照，但数据库是权威来源；创建、改名、启用/禁用、注册和重新注册成功后原子更新快照。

注册数据库不可用时：

- 动态注册和动态客户端管理进入明确的不可用状态；
- 数据库健康检查失败后拒绝新的动态认证和注册；已经完成认证的动态连接可维持到当前连接结束，但不得从陈旧快照建立新连接，以免遗漏禁用或换钥；
- 静态 TOML 客户端、既有中继/P2P 功能和只读观测不得被动态注册故障拖垮；
- Web 显示中文健康告警，且不能误报操作成功。

权威库打开、完整性检查或迁移失败必须失败关闭，绝不能隔离后自动创建空权威库。备份必须使用 SQLite 在线备份 API 或停服后一致复制数据库及 WAL/SHM；回滚同时恢复二进制、schema 兼容的权威库和配置。

数据库容量、令牌数量、活动动态客户端数量、墓碑数量和审计记录分别有硬上限。活动客户端上限不计墓碑。审计记录按配置的保留期和数量上限批量淘汰最旧记录，但涉及权限变更的当前事务必须先成功写入审计，否则管理操作失败。达到预警水位时 Web 显示告警。禁用客户端保留历史；删除采用墓碑语义并要求二次确认。墓碑默认保留 90 天且有独立上限，到期后由有界后台任务清除权威凭据和原客户端 ID，并把关联历史的显示名固化为“已删除客户端”，随后允许该 ID 被新内部 UUID 复用；清除不得删除观测历史或阻塞认证。

## 8. Web 纯中文与客户端管理

登录、导航、总览、客户端详情、会话、筛选、排序、空状态、时间单位、图表、错误、确认框和无障碍标签全部使用中文。API 字段、URL 路由、查询参数和协议枚举保持稳定英文值，避免翻译破坏兼容性。

Web 新增“客户端”管理入口，支持：

- 新建客户端并一次性显示接入密钥；
- 为尚未绑定的客户端重新签发一次性接入密钥；
- 修改客户端 ID，校验非空、长度、字符范围和唯一性；
- 启用或禁用客户端；
- 为指定客户端生成重新注册密钥；
- 删除客户端，要求二次确认并明确历史保留策略。

页面只显示客户端 ID、在线状态、最后心跳、隧道数量、活动会话、流量、路径和最近会话，不显示内部 UUID、公钥、令牌哈希或私钥相关信息。

所有新增客户端管理写接口只接受 JSON POST，不改变既有登录表单和退出接口。管理写接口要求有效管理员会话、严格同源 `Origin`、`Content-Type: application/json`、固定请求体上限和与当前管理员会话绑定的 CSRF 令牌；令牌由登录成功后的同源页面元数据取得，登录和会话轮换时重新生成，退出时失效。其他方法返回 `405`，未认证返回 `401`，跨源或 CSRF 错误返回 `403`，版本冲突返回 `409`，校验错误返回 `422`。客户端记录 DTO 暴露整数 `revision`，改名、启停、令牌签发和删除均携带期望 revision 并以 CAS 更新。

每个管理写请求携带随机操作幂等 ID，服务端按管理员会话和接口有界保留结果摘要。非秘密操作重试返回原结果；一次性秘密已经生成但响应丢失时，只返回稳定的“操作已成功但密钥不可恢复”，管理员必须通过对应重新签发接口取得新密钥。所有写响应 `Cache-Control: no-store`，成功与失败均记录不含秘密的审计事件；重复提交不得重复创建、换钥或消费令牌。

最小写接口为：`POST /api/v1/clients` 新建并返回一次性接入密钥；`POST /api/v1/clients/{client_id}/enrollment-token` 为未绑定记录重新签发；`POST /api/v1/clients/{client_id}/rename` 改名；`POST /api/v1/clients/{client_id}/state` 启用或禁用；`POST /api/v1/clients/{client_id}/reenrollment-token` 返回一次性重新注册密钥；`POST /api/v1/clients/{client_id}/delete` 墓碑删除。路径中的客户端 ID 必须按相同规范解析，响应只包含显示字段、revision 和稳定错误码，除令牌签发成功响应外不含秘密。

管理操作的即时语义如下：

| 操作 | 新认证 | 已在线会话 | 令牌 | 历史与名称 |
| --- | --- | --- | --- | --- |
| 改名 | 使用新 ID 投影，认证公钥不变 | 服务端发送带 revision 的身份更新事件，GUI/CLI 立即刷新显示 | 不变 | 内部 UUID 不变，历史立即以新 ID 展示 |
| 禁用 | 立即拒绝 | 立即终止控制、隧道、P2P 与数据会话 | 撤销全部未消费令牌 | 保留历史与 ID |
| 启用 | 允许当前公钥认证 | 不自动重建，由客户端正常重连 | 不自动生成 | 保留历史与 ID |
| 换钥 | 仅新公钥可认证 | 成功提交时终止旧凭据的全部会话 | 消费当前并撤销其他旧令牌 | 内部 UUID、ID 与历史不变 |
| 删除 | 墓碑保留期内永久拒绝 | 立即终止全部会话 | 撤销全部令牌 | 保留墓碑和历史；墓碑清除前 ID 不复用 |

墓碑记录不出现在默认客户端列表，可在保留期内的历史筛选中以“已删除”查看；清除后旧历史统一显示“已删除客户端”。普通 Web 页面仍不显示内部 UUID 或公钥。

## 9. GUI 功能闭环

GUI 保留六个页签：

- **连接**：服务器地址、真实连接/注册状态、服务端返回的客户端 ID、连接代数、错误提示、上传/下载总量与速率。
- **隧道**：当前 active generation 的名称、协议、本地地址、远端端口、接受/拒绝状态和错误；换代或断线清除旧数据。
- **遥测**：本机 CPU、内存、网络和 Rustgo 逻辑流量曲线，两秒采样，每个序列最多 300 点。
- **P2P**：出口名称、Relay/Direct、选中地址和更新时间；无活动路径时显示中文空状态。
- **日志**：真实 tracing 日志，最多 1000 行，支持级别筛选、复制和清空。
- **配置**：管理单个 `client.toml`，支持服务器地址、证书/指纹、设备私钥路径、隧道、P2P exports/forwards、文件选择、设备密钥生成、保存和重新加载。

同一连接代的状态、隧道、流量和 P2P store 必须来自同一个 `ClientApp`。不得使用与实际客户端无关的占位 watch 通道，也不得将可用数据固定传为 `None`。重复点击连接必须同步取消旧代，不能并行启动同一身份。

配置表单先在内存校验，通过后写临时文件、刷新并原子替换。失败时保留原文件。连接相关配置变化提供“保存并重新连接”；读取或浏览配置不得自动重连。配置损坏显示具体字段错误，不得自动覆盖为默认配置。

## 10. CLI 与 GUI 一致性

`rustgoc` 库提供统一的注册状态机、令牌解析、指纹验证、设备密钥生成、注册消息和本地持久化。CLI 与 GUI 只负责输入输出适配。

CLI 在有终端时安全提示输入；无人值守模式从标准输入或专用环境变量读取。GUI 使用不会回显的一次性输入框。两者对缺失密钥、损坏密钥、首次注册、重新注册和正常认证必须产生相同的状态分类与服务端结果。

## 11. 失败隔离与资源上限

- 注册失败不得终止服务端现有中继、P2P、Web 只读观测或静态客户端。
- GUI 配置或采样失败不得卡住 UI 线程或连接 runtime。
- 日志、图表、托盘事件、注册尝试、令牌表和动态客户端表都有固定上限。
- 令牌错误与公钥冲突使用限速且不可枚举的公开响应。
- 客户端关闭、断开或换代必须取消并加入旧任务，释放套接字与敏感内存。
- 服务端客户端 ID 改名通过同一权威记录立即投影，不修改认证公钥或历史归属。

## 12. 测试策略

遵循仓库约定，以功能测试为主，不新增细碎单元测试；实现过程中不运行测试，最终验收阶段统一执行。

必须覆盖以下真实功能路径：

1. Web 创建客户端、只显示一次接入密钥，CLI 首次注册、自动生成设备密钥、建立真实隧道。
2. 未声明身份模式且无私钥的 GUI 进入首次注册界面，接入密钥不落盘；动态模式缺钥进入重新注册界面，显式静态模式缺钥显示配置错误。注册后状态、隧道、流量、遥测、P2P 和日志来自同一个真实实例。
3. Web 修改客户端 ID 后总览、详情、会话、日志和客户端显示立即更新，不要求重连。
4. 禁用动态客户端后拒绝新认证且保留历史。
5. 私钥损坏后普通连接不删除文件；显式重新注册使用定向令牌换钥并恢复连接。
6. 错误、过期、重放、并发消费和用途错误令牌均失败，不能产生半绑定状态。
7. 服务端提交前后、响应丢失、本地候选提升和进程重启等崩溃点均能通过 pending 候选恢复，且接入密钥不落盘。
8. 先签发重新注册密钥 A，再签发 B；B 成功后 A 必须失败。并发消费只能有一个成功。
9. 禁用、换钥和删除必须终止既有控制、隧道、P2P 与数据会话；改名通过版本化事件立即更新在线客户端显示。
10. 服务器指纹不符、静态/动态名称或公钥冲突、数据库只读、损坏、迁移失败和容量上限均失败关闭且不影响静态客户端。
11. 未登录、跨源、错误方法、错误内容类型、超限请求、重复提交及并发改名/删除均按稳定状态码失败；一次性密钥响应不可缓存、刷新不可恢复。
12. 重复连接只保留一个代，断开与关闭加入所有子任务；GUI 配置原子替换失败时原配置保持不变。
13. Web 浏览器实际走完纯中文登录、总览、客户端新增/改名/禁用/重新注册、墓碑删除和错误状态。
14. 使用 SQLite 一致备份验证 WAL 状态下的恢复，并实际演练一次失败部署后的二进制、配置与权威库回滚。
15. 用升级前可正常工作的历史配置验证中文、大小写敏感静态名称和旧登录表单不变；显式静态缺钥不得进入动态注册，未声明模式缺钥必须等待接入密钥。
16. 首次与重新注册 pending 在重启后按各自类型恢复；令牌地址与旧配置冲突经确认后即使崩溃，也按 pending 中的地址与指纹恢复。
17. 首次令牌丢失、过期、响应中断和并发重新签发时，旧令牌全部失效且新令牌可完成绑定。
18. 证书轮换只通过显式重新注册完成，验证旧会话终止、新指纹与新设备密钥原子生效及失败恢复。
19. 活动记录达到上限时墓碑不占活动名额；墓碑到期清除后 ID 可复用，旧历史仍显示为“已删除客户端”且不归属新记录。

最终门禁包括 Windows 与 Linux 的格式检查、workspace Clippy、全量功能测试、release 构建、CLI/GUI 自检及真实服务器部署验证。任何失败都停止发布。

## 13. 部署与回滚

部署前备份注册数据库、服务端配置和旧二进制。新二进制先对生产配置执行只读 `check`，再启动并验证中继端口、Web、静态客户端、动态注册、SQLite 健康和真实隧道。

数据库迁移或端到端验证失败时恢复旧二进制与数据库备份，原当前版本保持不变。不得因清理临时文件失败而掩盖部署失败状态。

## 14. 验收标准

1. Web 所有用户可见文本为中文，浏览器真实操作无英文残留。
2. Web 可创建、改名、禁用和重新注册动态客户端，且不显示内部 UUID 或公钥。
3. 一次性接入密钥只显示一次、不持久化明文、不可重放，并携带服务器地址与证书指纹。
4. 未声明身份模式且无私钥的 CLI/GUI 不报初始化失败，而进入等待首次注册状态；动态模式缺少或损坏私钥进入 `ReRegistrationRequired`；显式静态模式缺钥保持配置错误。注册成功后自动使用本地设备密钥。
5. 私钥损坏只有在用户显式重新注册时才删除，定向重新注册密钥成功替换服务端绑定。
6. 客户端 ID 改名立即生效且不割裂历史，不影响当前认证和隧道。
7. GUI 六个页签读取真实同代状态，流量、隧道、遥测、P2P 与日志可见且有界。
8. CLI 与 GUI 共享同一注册实现，静态 TOML 客户端与既有协议继续兼容。
9. Windows/Linux 全量门禁和真实服务器端到端部署验证通过，失败时可回滚。
