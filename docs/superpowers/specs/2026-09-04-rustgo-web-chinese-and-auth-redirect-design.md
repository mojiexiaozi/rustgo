# Rustgo Web 中文化与未鉴权跳转设计

## 目标

将嵌入式 Web 仪表盘改为仅简体中文界面，并让浏览器在未鉴权访问仪表盘页面时自动进入登录页，同时保持 JSON API 的鉴权响应契约不变。

## 范围

- 中文化 `login.html`、`index.html`、`login.js` 和 `app.js` 中所有用户可见文案，包括标题、导航、表单、筛选项、状态、错误、空状态、时间描述、指标说明和图表文字。
- 将页面语言声明设为 `zh-CN`，日期时间使用明确的中文区域格式。
- 保留 Rustgo、CPU、TCP、UDP、P2P、QUIC、MiB 等产品名、协议名和标准单位。
- 未鉴权访问仪表盘 HTML 入口 `/` 时返回 `302 Found`，`Location: /login`。
- 未鉴权访问 `/api`、`/api/**` 以及具体 `/api/v1/**` 路由时继续返回 `401` JSON，不重定向。
- 登录成功后进入 `/`；仪表盘会话失效时，现有前端请求逻辑继续跳往 `/login`。

## 非目标

- 不增加中英文切换或通用国际化框架。
- 不改变页面布局、视觉样式、认证算法、Cookie 属性、会话生命周期、API 数据结构或错误码。
- 不翻译服务端日志、配置字段、JSON 字段名和客户端 GUI。

## 实现设计

静态 HTML 中的固定文字直接替换为简体中文。JavaScript 运行时生成的文字也直接使用中文常量，避免为了单语言界面引入文案表或依赖。设备名、隧道名及其他自由文本动态数据保持原值；`active`、`closed`、路径类型等有限枚举在前端映射为中文，TCP、UDP、P2P、QUIC 等协议缩写保留。不得为中文显示修改 API JSON。

页面鉴权与 API 鉴权保持分层：`assets::index` 在 Cookie 验证失败时明确返回 `StatusCode::FOUND`（302）并设置 `Location: /login`，不使用会产生 307 的临时重定向助手；`api_boundary` 和各 API 路由继续调用现有的 `authentication_required` JSON 响应。登录页及其 CSS、JavaScript 仍允许匿名读取。

## 错误与边界行为

- 浏览器直接访问 `/` 且没有、损坏或过期的 `rustgo_session`：跳转 `/login`。
- 浏览器已加载仪表盘后会话过期：下一次 API 请求收到 `401`，前端跳转 `/login`。
- 程序直接请求受保护 API 且未认证：获得原有 `401 authentication_required` JSON。
- 登录凭据错误、请求来源不合法或达到速率限制：沿用现有状态码和安全响应，只中文化浏览器展示的通用失败提示，不泄露具体原因。

## 验收

遵循仓库约定，不新增单元测试，也不在编写过程中运行测试。更新既有功能测试中的英文文案断言，并增加 `/` 的 `302` 与 `Location` 回归断言。最终验收统一运行 `web_assets`、`web_auth` 和 `web_api` 功能测试，确认：

1. 登录页和仪表盘不存在面向用户的英文界面文案，保留的仅为约定的技术名词、单位和动态数据。
2. 未鉴权的 `/` 请求返回 `302` 且指向 `/login`。
3. 未鉴权 API 仍返回 `401` JSON。
4. 有效登录 Cookie 仍可访问 `/` 和 API，退出及会话过期行为不变。
