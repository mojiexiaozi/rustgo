# 服务端统一管理所有客户端隧道

日期：2026-09-15

## 已确认的目标

服务器 Web 管理端显示、添加和删除所有类型的客户端隧道：普通 TCP/UDP tunnels、P2P exports 和 forwards。服务端持久保存配置；在线客户端自动应用，离线客户端上线后同步。CLI 与 GUI 使用相同同步逻辑。

## 现状与选择

Web Inventory 当前仅有三类名称列表。普通隧道注册包含名称、协议和服务器端口，不包含客户端目标地址。客户端运行时根据启动配置构建 TCP、UDP 和 P2P 资源，尚无远程配置更新流程。

采用服务端保存期望配置、客户端回报实际结果的方案。仅发送临时命令无法支持离线修改；直接远程编辑客户端文件又会引入路径、权限和 GUI 覆盖问题，因此不采用这两种方案。

## 数据与配置所有权

- 一个客户端配置快照包含 tunnels、exports、forwards 三个完整集合及递增 revision；每项以类型和名称唯一定位。
- 普通隧道保存 name、protocol、local_addr、remote_port；export 保存 name、protocol、local_addr、allowed_peers；forward 保存 name、peer、export、listen_addr。forward 的传输协议由目标 export 决定。
- 新客户端第一次上报时导入现有三类配置。导入成功后，服务器成为这三类集合的权威来源，删除到空集合也是有效配置，不能重新导入旧文件使项目复活。
- 同步记录绑定经过认证的稳定客户端身份。动态客户端改名保持配置；静态客户端使用独立身份命名空间，防止同名设备继承配置。身份被删除后不能向后续同名设备下发旧配置。
- 服务端保存最后上报的详情以及期望配置；离线详情明确标记为历史状态。尚未首次完整上报的旧设备不能被误当成空配置接管。
- 客户端连接该服务器时在注册资源之前获取权威快照；服务器不可达或同步存储不可用时，不回退注册已被删除的本地项目。
- 本地身份、证书和连接参数仍由现有配置负责。GUI 对已接管的三类项目展示服务器管理状态，避免本地保存覆盖远程变更。

## 同步与运行时

扩展版本协商后的控制协议，增加有大小限制的配置上报、快照下发、更新通知和结果回报。旧版本保留既有连接行为，管理页面显示“客户端需升级”，不发送其无法识别的消息。

管理员的增删请求在服务端事务中检查 expected_revision、校验完整候选配置并提交新版本，然后通知在线设备。通知丢失时通过重连同步恢复；重复版本幂等处理，旧回报不能覆盖新版本的状态。

首版通过有序重建该客户端运行时应用新版本：停止旧代次的监听、流和 P2P 资源，清理完成后使用新快照重新注册。此过程可能短暂中断该客户端其他正在使用的隧道，Web 操作处需要明确说明。其他客户端不重启。

回报同时区分已接收版本和每项运行结果。提交成功只表示已保存，不表示已监听。无活动连接的 export 或 forward 可以是就绪，不能因此显示为连接失败。

新增 P2P 项目要求客户端已有有效 P2P 基础配置并启用 P2P；不满足时页面给出明确前置条件，不虚报应用成功。已有直连、回退和端口范围策略保持由客户端配置控制。

## 删除和错误语义

- 删除后关闭对应监听与活动会话。删除 export 还会撤销其授权和相关 P2P 会话。
- 其他客户端引用被删 export 的 forward 保留并显示目标不可用，不能悄悄级联删除其他设备配置。
- 校验名称、地址、端口、数量和 export 权限列表；复用现有配置规则。revision 冲突要求刷新后重试。
- 端口实际绑定失败显示在对应项目，不改占用端口的服务；例如服务器 SSH 占用 22 时报告冲突。
- 存储提交失败不通知应用；客户端应用失败保留期望版本和错误，不误标成功，也不恢复已删除项目。
- offline、pending、applying、ready、failed 与旧版本不支持必须可以区分；断线后旧成功结果不得继续显示成当前在线就绪。

## 服务端与 Web 边界

新增专用配置存储模块，采用项目已有 SQLite 和迁移方式，覆盖静态及动态客户端，不能以 enrollment.enabled 作为静态客户端使用此功能的前提。数据库路径通过服务器配置定义，沿用私有目录和权限要求。

管理 API 提供指定客户端的三类详情及新增、删除操作。写请求复用管理员会话、Origin、CSRF 和 JSON 校验；身份来自经过认证的客户端连接，不能相信上报载荷中的客户端名称。审计记录操作人、客户端、类型、名称、版本和结果，不记录凭据。

客户端详情页提供三类列表和对应添加表单、删除入口，显示待同步/实际状态与错误。export 表单明确展示允许的客户端列表，空列表沿用现有“允许所有已授权客户端”的语义。forward 表单填写目标客户端、export 和本地监听地址。

## 验证与交付

1. 存储：首次导入、空快照、版本冲突、重启恢复、身份隔离与改名/删除。
2. 协议：版本兼容、超限拒绝、重复通知、旧回报和断线重连。
3. 运行时：TCP/UDP 实际数据转发；export/forward 的直连或回退；三类删除后监听与会话清理。
4. 同步：离线增删上线恢复、客户端与服务器分别重启、失败状态可见，旧本地配置不复活。
5. Web：权限与 CSRF 校验、三类表单、详情、状态以及服务端端口冲突提示。
6. GUI 和 CLI 共享核心流程；验证 GUI 已接管提示和服务器修改后的刷新。
7. 完成格式、相关单元/集成测试和构建检查后，沿用已有备份与回滚流程更新服务器及本地客户端，检查健康接口和真实连接。

## 本次不包含

不新增隧道类型，不更改 P2P 路由算法，不新增本地与远程双向冲突合并，不承诺配置变更期间现有连接无中断。
