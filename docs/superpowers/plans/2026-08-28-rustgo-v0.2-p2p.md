# Rustgo V0.2 P2P Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add authenticated device-to-device TCP and UDP services with QUIC/UDP preference, native TCP hole punching, bounded complex-NAT discovery, and end-to-end encrypted relay fallback.

**Architecture:** Add focused rendezvous, NAT, and path crates below the existing client/server executables. Extend the authenticated control protocol for signed candidate exchange, race direct transports behind one stream/datagram interface, and retain the V0.1 relay as a delayed fallback that carries peer-encrypted frames.

**Tech Stack:** Rust 2024, Tokio, async-trait, Serde/Postcard, Ed25519, X25519, HKDF-SHA256, ChaCha20-Poly1305, Quinn/QUIC, Rustls 1.3, socket2, proptest, Linux network namespaces, PowerShell/Bash process E2E.

**Spec:** `docs/superpowers/specs/2026-08-28-rustgo-v0.2-p2p-design.md`

## Global Constraints

- Preserve all V0.1 `[[tunnels]]`, command-line, TLS, logging, and relay behavior.
- TOML remains strict; unknown fields are errors and relative paths resolve against the configuration file.
- Missing or empty `allowed_peers` means allow every registered, enabled, authenticated peer and emits a warning; a non-empty list is enforced by the provider.
- Prefer QUIC/UDP, then native TCP direct, then end-to-end encrypted relay; direct connectivity is never guaranteed.
- Use fixed discovery ports `7443/udp` and `7444/udp`; candidate and prediction work is strictly bounded.
- Preserve TCP byte-stream and UDP datagram semantics on every path.
- Production logs remain single-line human-readable text and never expose secrets or application payloads.
- All new Rust crates and modules use `#![forbid(unsafe_code)]`.

---

## File structure

- `crates/rustgo-config/src/p2p.rs`: P2P TOML models, port ranges, exports, forwards, and authorization semantics.
- `crates/rustgo-rendezvous/`: bounded rendezvous wire types and state machine without socket ownership.
- `crates/rustgo-crypto/src/peer.rs`: signed peer transcript, X25519 agreement, HKDF keys, and AEAD frame protection.
- `crates/rustgo-nat/`: candidate gathering, observation analysis, bounded prediction, UDP checks, and TCP simultaneous-open.
- `crates/rustgo-path/`: transport-neutral path state machine, race orchestration, health, fallback, and recheck.
- `crates/rustgo-transport/src/quic.rs`: QUIC endpoint and peer session adapters.
- `crates/rustgo-transport/src/peer_tcp.rs`: framed encrypted native TCP peer transport.
- `crates/rustgos/src/observation.rs`: two-port UDP observation service.
- `crates/rustgos/src/rendezvous.rs`: authenticated online-peer/session coordinator.
- `crates/rustgoc/src/exports.rs`: provider export authorization and local target opening.
- `crates/rustgoc/src/forwards.rs`: consumer TCP/UDP local listeners.
- `crates/rustgoc/src/peer.rs`: peer-session orchestration and path adapters.
- `tests/netns/`: Linux namespace topology harness.
- `tests/e2e/tests/p2p.rs`: real-process portable P2P and forced-fallback tests.
