# Rustgo V0.4 GUI Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a desktop GUI client `rustgoc-gui` that embeds the `rustgoc` library in-process and provides visual connection management, tunnel health, bounded live logs, local telemetry charts, a P2P path panel, and a Windows-only system tray, without changing headless client or server behavior.

**Architecture:** One new workspace crate `crates/rustgoc-gui` with three layers: a runtime layer owning a small Tokio runtime and per-generation `CancellationToken`s; a display-free state layer of view models (`ConnectionViewModel`, tunnel rows, bounded log ring, bounded telemetry history, P2P snapshot polling) that is unit-testable headless; and an `eframe`/`egui` presentation layer that only reads state. Two small `rustgoc` library additions expose observation surfaces the GUI needs: a public traffic snapshot and a public P2P path-status store fed by the existing orchestration ownership boundaries.

**Tech Stack:** Rust 2024, existing `rustgoc`/`rustgo-config`/`rustgo-observability`/`rustgo-transport` libraries, Tokio, tokio-util, clap (derive), `tracing`, eframe/egui with the glow renderer, egui_plot, `tray-icon` (Windows target only, pure Win32).

**Spec:** `docs/superpowers/specs/2026-09-02-rustgo-v0.4-gui-client-design.md`

## Global Constraints

- Preserve `#![forbid(unsafe_code)]` in every crate including the new GUI crate, human-readable logs, and all V0.1/V0.2/V0.3 server and headless-client behavior.
- The GUI embeds the `rustgoc` library; it must not fork, wrap, or reimplement protocol, relay, P2P, reconnection, or authentication logic. No new listeners, ports, or protocol messages.
- Every GUI-owned collection is bounded: 1,000 log lines, 300 telemetry points per series, 64 tray events; overflow drops oldest.
- The GUI never calls `rustgo_transport::logging::init_logging`; it installs its own bounded ring subscriber. stderr formatting remains available behind `RUST_LOG` for headless runs.
- Windows and Linux are both first-class. The tray is the only platform-gated feature (`[target.'cfg(windows)'.dependencies]` + `cfg(windows)`); Linux builds never link GTK, libappindicator, or any tray runtime.
- View models and state transitions live in display-free modules; tests must run headless on both platforms without xvfb or a window server.
- Follow repository testing policy: implement each task without intermediate test runs; run the named concentrated verification only at the task's final checkpoint. Run the complete acceptance matrix after all tasks.
- Commit only scoped files after each task; do not push, deploy, or change production services.
- egui/eframe and egui_plot versions are pinned together in `workspace.dependencies` (0.36.x line, glow renderer, `default-features = false` with `["glow", "default_fonts", "x11", "wayland"]`).

Public `snapshot()` and `version()`; `record()`/`remove()` are `pub(crate)`. Timestamps use the client's existing monotonic-to-Unix conversion.
