# 服务器管理客户端隧道

服务器和客户端都升级后，在服务器配置中加入独立的配置数据库路径：

```toml
[managed_tunnels]
database_path = "/var/lib/rustgo/rustgo-managed-tunnels.db"
```

数据库父目录必须已存在且服务账户可写。此功能不依赖动态客户端注册；静态授权客户端也能使用。未配置该节时，客户端保持原有本地配置模式。旧客户端继续连接，但管理页面提示升级。

登录服务器 Web 管理端，打开客户端详情中的“隧道配置管理”。可以查看和增删：

- TCP/UDP 隧道：名称、本地目标地址、服务器端口。
- P2P 导出：名称、协议、本地目标、允许访问的客户端。允许列表为空表示所有已授权客户端。
- P2P 转发：名称、目标客户端、目标导出、本地监听地址。协议由导出决定。

客户端首次完整同步时，服务器导入本地的三个配置集合。此后这些集合以服务器保存的版本为准；删空也是有效配置，重连不会重新导入本地旧项目。客户端 GUI 和服务器页面都能修改这些项目。客户端卡片修改后点击“保存到服务器并生效”，使用设备自身身份同步配置，无需管理员密码。客户端身份、服务器地址和 P2P 基础策略仍在本地配置中管理。

客户端保存携带草稿开始编辑时的修订号；若服务器配置已变更，会提示冲突并保留草稿，不覆盖新配置。“重新加载服务器配置（丢弃草稿）”会重新连接并读取服务器版本。未保存草稿仅保留在当前客户端进程中。客户端写入需要两端支持 V0.5 协议，旧服务器会明确提示升级，原有连接仍兼容。

添加 P2P 项目前，在客户端启用有效的 P2P 基础配置并重连。服务器配置修改先保存，在线客户端自动重连并应用，离线客户端上线后应用。此过程会短暂中断该客户端的其他连接。状态区分等待应用、已就绪和失败；保存成功不代表端口绑定成功。

删除导出会关闭提供方对应会话。引用它的其他客户端转发保留，并显示目标不可用。不要将服务器 SSH 等服务已经占用的端口用于隧道；端口冲突会显示为失败，不会关闭原服务。

新版客户端和服务器会显示具体中文原因，例如“服务器端口 10022 已被占用，请更换远程端口（错误码 11）”。无权监听端口使用错误码 12；旧服务器返回错误码 8 时只能确定隧道被拒绝，界面会提示检查配置、数量限制和服务端日志，不会把所有拒绝都误报为端口占用。

部署或回滚时同时备份服务器配置、二进制和此数据库。服务器配置检查会打开配置数据库，在线预检应使用独立的临时数据库路径。
